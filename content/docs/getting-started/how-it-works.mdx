Vantage operates fundamentally as a network interceptor and deterministic diffing engine. To get the most out of Vantage, it helps to understand how traffic flows during recording and replaying.

## The Recording Flow

During a recording session, Vantage sits transparently between your client (Postman, browser, or automated tests) and your backend API.

1. **Database Provisioning**: If configured in `vantage.config.yaml`, Vantage spins up an ephemeral database (via Testcontainers) and injects the connection string into your application before booting it.
2. **Proxy Interception**: Running `vantage record --proxy <port>` boots a lightweight HTTP reverse proxy (defaulting to port `6789`).
3. **Forwarding**: You send your test traffic to port `6789`. Vantage forwards each request to your actual backend application, waits for the response, and relays it back to the client.
4. **Capture & Serialize**: On each roundtrip, Vantage captures the HTTP method, path, headers, query parameters, request body, and response body, serializing them into a structured YAML test case.
5. **Storage**: The test case is saved chronologically in `.vantage/test-set-N/tests/<method>-<slug>-<counter>.yaml`.

## The Replay Flow

When running `vantage test`, the proxy server is not needed. Instead, the Vantage CLI acts directly as an automated HTTP test runner.

1. **Database Provisioning**: If configured, Vantage spins up ephemeral Docker databases (via Testcontainers) and sets up a pristine database state before your app even boots.
2. **Chronological Ordering**: The engine scans the `.vantage` folder and loads the test set. Tests are sorted by their original recording timestamps to guarantee that stateful workflows (e.g., `POST /todos` followed by `GET /todos`) execute in exact sequential order.
3. **Sanitization**: Hop-by-hop headers (such as `Host`, `Content-Length`, and `Connection`) are stripped from the recorded request so the HTTP client can recalculate them dynamically.
4. **Execution**: The CLI fires the HTTP requests against your live target application (`--target`).
5. **Noise Filtering**: Before comparing responses, Vantage's noise engine masks volatile data (UUIDs, timestamps, dates, JWTs, and any custom fields configured in `vantage.config.yaml`).
6. **Diffing**: A deep JSON diff is performed on the sanitized bodies, alongside a status code check and header verification. If any unexpected changes occur, a colored terminal diff highlights the regression.

## Why Reverse Proxy?

Vantage deliberately uses a transparent reverse proxy architecture rather than in-app SDKs or middlewares:

- **Zero Code Modification**: You never have to install SDK dependencies or modify server initialization logic in your application.
- **Truly Language-Agnostic**: Works seamlessly with any HTTP backend—Node.js (Express, Fastify, NestJS), Python (FastAPI, Django, Flask), Go, Java (Spring Boot), Ruby on Rails, Rust, or any standard HTTP service.
- **Production Safety**: No testing libraries or monkey-patching code ever risk leaking into your production builds.
- **Clean Interception**: Vantage cleanly captures exact raw headers, status codes, and payloads right off the network wire.
