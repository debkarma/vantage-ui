Running Vantage in GitHub Actions is incredibly straightforward, provided you understand how Testcontainers interacts with Docker in a CI environment.

## The Docker Dependency

If your `vantage.config.yaml` uses the `containers` block to spin up databases, your CI runner **must** have Docker installed and the Docker socket available. 

Fortunately, the standard `ubuntu-latest` runner provided by GitHub Actions comes with Docker pre-installed and fully configured.

## The Workflow File

Create a file at `.github/workflows/vantage-tests.yml`:

```yaml
name: API Regression Tests

on:
  push:
    branches: [ "main", "develop" ]
  pull_request:
    branches: [ "main" ]

jobs:
  test:
    name: Run Vantage Suite
    runs-on: ubuntu-latest
    
    steps:
      - name: Checkout Repository
        uses: actions/checkout@v4
        
      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: 'npm'
          
      - name: Install Dependencies
        run: npm ci
        
      - name: Install Vantage CLI
        run: npm install -g vantage-cli
        
      - name: Run Vantage Tests
        # The --ci flag removes terminal spinners
        # The --reporter=junit generates a vantage-report.xml file
        run: vantage test --ci -c "npm start" --reporter=junit
        
      - name: Publish Test Report
        # This third-party action parses the XML and creates annotations on the PR
        uses: mikepenz/action-junit-report@v4
        if: success() || failure() # Always publish the report, even if tests fail
        with:
          report_paths: 'vantage-report.xml'
          check_name: Vantage Test Results
```

## Security Best Practices

### Environment Variables
Never hardcode production API keys or secrets in your `vantage.config.yaml`. Instead, inject them via GitHub Secrets:

```yaml
      - name: Run Vantage Tests
        run: vantage test --ci -c "npm start"
        env:
          STRIPE_SECRET_KEY: ${{ secrets.TEST_STRIPE_SECRET_KEY }}
          SENDGRID_API_KEY: ${{ secrets.TEST_SENDGRID_API_KEY }}
```

### Self-Hosted Runners
If you are using self-hosted runners instead of `ubuntu-latest`, ensure the user running the GitHub Actions agent has permissions to access the Docker daemon (usually by adding the user to the `docker` group).
