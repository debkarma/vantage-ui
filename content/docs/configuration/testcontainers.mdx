---
title: Testcontainers
description: Spin up ephemeral databases automatically using Docker.
---

Testing stateful APIs is notoriously difficult because tests mutate database records. If a test deletes a user, subsequent test runs might fail because that user record no longer exists.

Vantage solves this by deeply integrating with **Testcontainers**. Vantage can automatically spin up fresh, ephemeral Docker containers (PostgreSQL or MongoDB) before running your tests, seed them with initial state, and tear them down immediately upon completion.

This guarantees an isolated, repeatable slate for every test run without requiring manual database resets.

## Configuration Schema

Containers are configured in the `containers` array of `.vantage/vantage.config.yaml`:

```yaml
containers:
  - type: postgresql # or 'mongodb'
    image: postgres:15-alpine # optional custom image
    seed: ./test/seed.sql # optional seed script
    env_var: DATABASE_URL # required env var to inject
```

### Supported Fields

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `type` | `'postgresql' \| 'mongodb'` | **Yes** | The database engine to launch. |
| `image` | `string` | No | Custom Docker image tag. Defaults to `postgres:15` or `mongo:6.0`. |
| `seed` | `string` | No | Path to a `.sql`, `.js`, or `.sh` seed script mounted into `/docker-entrypoint-initdb.d/`. |
| `env_var` | `string` | **Yes** | The environment variable name where the dynamic connection string will be injected. |

> [!NOTE]
> Currently, Vantage natively supports **PostgreSQL** and **MongoDB**. Generic containers or other engines like Redis are not supported.

## Examples

### PostgreSQL with SQL Seed

```yaml
containers:
  - type: postgresql
    image: postgres:15-alpine
    seed: ./fixtures/init.sql
    env_var: DATABASE_URL
```

When started, Vantage mounts `./fixtures/init.sql` into the container's entrypoint directory, ensuring tables and initial rows are populated before your app receives traffic.

### MongoDB with Init Script

```yaml
containers:
  - type: mongodb
    image: mongo:6.0
    seed: ./fixtures/init-mongo.js
    env_var: MONGO_URI
```

## How It Works

1. **Random Port Allocation**: Testcontainers binds to an ephemeral, randomly assigned host port (not fixed ports like `5432` or `27017`). This avoids port collisions with local databases or concurrent CI jobs.
2. **Readiness Verification**: Vantage waits for internal database health checks to confirm the instance is ready to accept connections.
3. **Connection String Formatting**:
   - **PostgreSQL**: Automatically ensures the connection string uses the standardized `postgresql://` URI scheme (compatible with Prisma, Drizzle, and SQLAlchemy).
   - **MongoDB**: Automatically appends `?directConnection=true` to ensure drivers (like Mongoose) communicate directly with the container host rather than attempting internal replica topology discovery.
4. **Environment Injection**: Vantage injects the connection string into the designated `env_var` (e.g. `DATABASE_URL`).
5. **Teardown & Cleanup**: Once tests complete—or if a run is interrupted via `Ctrl+C` (`SIGINT`)—Vantage halts and destroys the containers cleanly.

> [!WARNING]
> Your environment must have Docker installed and the Docker daemon running to use Testcontainers.
