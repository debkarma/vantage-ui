---
title: Noise Filtering
description: Configure Vantage to ignore dynamic data like timestamps, IDs, and noisy headers.
---

APIs frequently return dynamic data—such as auto-generated IDs, timestamps, or request traces. If Vantage strictly compared these fields during replay, tests would fail simply because a `createdAt` timestamp from yesterday will never match a timestamp generated today.

Vantage provides multiple complementary mechanisms to eliminate this noise: **Header Filtering**, **Body Field Filtering**, **Smart Auto-Masking**, and **Recording Path Ignoring**.

## Header Filtering

The `noise.headers` array defines HTTP headers that are stripped from both expected and actual responses before running diff assertions. Matching is always case-insensitive.

```yaml
noise:
  headers:
    - Date
    - ETag
    - X-Request-Id
    - Content-Length
    - Access-Control-Allow-Origin
    - Vary
    - X-Custom-Trace-Id
```

Vantage defaults to ignoring:
- `Date`
- `ETag`
- `X-Request-Id`
- `Content-Length`
- `Access-Control-Allow-Origin`
- `Vary`

> [!NOTE]
> Specifying custom headers in `noise.headers` replaces the default list. Include the default headers alongside any proprietary headers if you wish to keep them ignored.

During diffing, Vantage also performs a **subset comparison** on headers: only headers captured in the original recorded test case are asserted against the replay response.

## Body Field Filtering

The `noise.body_fields` array allows you to strip specific keys within JSON response bodies using dot-notation.

```yaml
noise:
  body_fields:
    - _id
    - data.createdAt
    - user.metadata.lastLogin
```

### Array Support

Vantage automatically traverses top-level arrays and arrays located at the parent segment of a key:
- **Top-level arrays**: Specifying `id` will remove `id` from every object in an array payload like `[{ "id": 1, "name": "A" }]`.
- **Nested arrays**: Specifying `users.id` will remove `id` from every object in `{ "users": [{ "id": 1 }, { "id": 2 }] }`.

## Smart Auto-Masking

Configuring every single dynamic field manually can be tedious. Vantage includes **Smart Auto-Masking**, enabled by default via `noise.smart_masking`.

### In-Memory Replay Comparison

Unlike systems that mutate recorded data on disk, **Vantage preserves raw response bodies in your recorded YAML test cases**.

Smart Auto-Masking operates **in-memory during test diffing**:
1. Before running `diffJson()`, the engine deep-clones both the recorded (expected) body and the live (actual) replay body.
2. The engine scans both objects and normalizes matching string patterns into standard tokens.
3. Because both the expected and actual bodies receive identical token replacements, dynamic values match without corrupting your original recorded fixtures.

### What gets masked?

| Target | Regex / Type Matched | Normalized Mask Token |
|--------|----------------------|-----------------------|
| **Timestamps** | ISO-8601 strings and `Date` instances | `<AUTO_MASKED_DATE>` |
| **UUIDs** | UUID v1 through v5 (`8-4-4-4-12` hex) | `<AUTO_MASKED_UUID>` |
| **JWTs** | `eyJ...` formatted JSON Web Tokens | `<AUTO_MASKED_JWT>` |

### Disabling Smart Masking

If Smart Auto-Masking normalizes values that you need to assert strictly, disable it under the `noise` section in `vantage.config.yaml`:

```yaml
noise:
  smart_masking: false
```

## Recording-Time Path Ignoring

In addition to response diff filtering, Vantage can filter out unwanted traffic at the proxy layer so it never creates test files in the first place:

```yaml
noise:
  ignore_paths:
    - /_next/
    - /__vite_ping
    - .ico
    - .css
    - .js
    - .png
    - .svg
```

Any incoming proxy request matching these substrings or file patterns is forwarded to your target application but bypassed by the recorder.
