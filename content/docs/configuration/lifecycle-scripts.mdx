Testing stateful applications often requires preparing external dependencies before tests execute—such as running database migrations, pushing schema definitions, or populating initial seed fixtures.

Vantage provides **Lifecycle Scripts** to run automated shell commands at predetermined points in the test execution workflow.

## The `scripts` Block

Lifecycle scripts are configured under the `scripts` object in `.vantage/vantage.config.yaml`:

```yaml
scripts:
  pre_test: "npx prisma db push && npx prisma db seed"
  post_test: "node ./scripts/cleanup.js"
```

| Field | Type | Description |
|-------|------|-------------|
| `pre_test` | `string` | Synchronous command executed before the target application boots and tests replay. |
| `post_test` | `string` | Teardown command executed after tests complete and the app is stopped. |

## Execution Lifecycle

Vantage coordinates containers, lifecycle scripts, application processes, and test replay in a strict, predictable sequence:

<Mermaid chart={`
graph TD
    A["1. Start Containers"] --> B["2. Inject Env"]
    B --> C["3. pre_test"]
    C --> D["4. Spawn App"]
    D --> E["5. Replay Tests"]
    E --> F["6. Stop App"]
    F --> G["7. post_test"]
    G --> H["8. Stop Containers"]
    H --> I["9. Generate Reports"]
`} />

1. **Containers Start**: Any Testcontainers defined in `containers` are pulled and started.
2. **Environment Assembled**: Connection strings (such as `DATABASE_URL`) are resolved from the ephemeral container ports.
3. **`pre_test` Runs**: The script executes synchronously with container environment variables injected. If `pre_test` fails, test execution is aborted immediately to avoid running against unready dependencies.
4. **Target App Boots**: If an application command is provided via the CLI (`-c` or `--app-command`), Vantage spawns your target application process with the injected environment variables and waits any specified `--delay`.
5. **Tests Replay**: Recorded HTTP interactions are replayed against the target application.
6. **Target App Stops**: Vantage gracefully terminates the child application process.
7. **`post_test` Runs**: Your teardown script executes inside a guarded cleanup block.
8. **Containers Destroyed**: Active Testcontainers are halted and removed from Docker.
9. **Reports Generated**: Test results and JUnit XML reports (in `--ci` mode) are written to disk.

## Common Use Cases

### Prisma Migrations & Seeding

Ensure an ephemeral PostgreSQL container has the latest schema before the application boots:

```yaml
scripts:
  pre_test: "npx prisma db push"
```

Because `pre_test` inherits the dynamic `DATABASE_URL` resolved from Testcontainers, Prisma targets the fresh container rather than your local development database.

### File-based Fixture Cleanup

Purge temporary uploads or mock storage generated during API testing:

```yaml
scripts:
  post_test: "rm -rf ./tmp/test-uploads"
```

## Error Handling & Cleanup Guarantees

- **`pre_test` Failures**: If your `pre_test` command exits with a non-zero exit code, Vantage catches the error, skips replaying tests, kills the application process (if already spawned), and immediately tears down containers to prevent orphaned resources.
- **`post_test` Guarantees**: `post_test` executes inside a `finally` block. Even if individual test cases fail or throw exceptions, `post_test` will run. Furthermore, even if `post_test` itself throws an error, container cleanup (`stopContainers`) is guaranteed.
- **Interrupts (`SIGINT`)**: If you cancel testing via `Ctrl+C`, Vantage's signal listener intercepts the event and tears down running containers before exiting.
