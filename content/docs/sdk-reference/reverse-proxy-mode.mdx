While the Express middleware is tightly integrated with Node.js, the **Reverse Proxy Mode** allows Vantage to record traffic for any HTTP server written in any language (Python, Go, Ruby, Rust, Java, etc.).

## The Architecture

When you start a recording session using the `--proxy` flag, Vantage spins up a lightweight HTTP proxy server. 

Instead of sending requests directly to your backend, you send them to the Vantage proxy. The proxy records the incoming request, forwards it transparently to your backend, captures the response, and forwards it back to you.

## Enabling the Proxy

To enable the proxy, use the `--proxy` flag followed by the port your application is listening on:

```bash
vantage record -c "python server.py" --proxy 8000
```

By default, the Vantage proxy will listen for incoming traffic on port `6789`. You can override this using the `--port` flag:

```bash
vantage record -c "go run main.go" --proxy 8080 --port 9000
```

## Supported Frameworks

The proxy mode is completely language and framework agnostic. Because it operates at the HTTP layer, it supports any backend that communicates via standard HTTP/1.1 protocols.

Examples of commonly proxied frameworks include:
- **Python**: FastAPI, Flask, Django
- **Go**: Gin, Echo, Fiber
- **Ruby**: Ruby on Rails, Sinatra
- **Rust**: Actix, Axum
- **Java**: Spring Boot

## Limitations

Because the proxy acts as a man-in-the-middle, it currently has a few limitations compared to the native Express SDK:

- **HTTPS termination**: The proxy only accepts HTTP traffic. If your local development server strictly enforces HTTPS, you must configure it to accept standard HTTP traffic during recording.
- **WebSockets**: WebSocket upgrading and streaming protocols (like SSE or gRPC) are not supported and will be dropped by the proxy.
