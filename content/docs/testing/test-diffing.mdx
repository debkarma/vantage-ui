---
title: Test Diffing & Assertions
description: How Vantage compares expected vs actual API responses.
---

Vantage eliminates the need to write manual assertions (`expect(res.body.name).toBe(...)`). Instead, it performs a deep structural diff between the recorded baseline and the live response received during replay.

## What Gets Compared

During test execution, Vantage evaluates three distinct layers of each HTTP transaction:

1. **Status Code**: The HTTP status code must match exactly (e.g., recorded `201` vs actual `201`).
2. **Headers (Subset Match)**: Vantage performs a case-insensitive subset comparison. The actual response must contain all headers recorded in the baseline YAML with matching values. Any *extra* headers added by server middleware or proxies (e.g. `X-Powered-By`, `Date`) are ignored.
3. **Body (Deep Structural Diff)**: JSON payloads are compared using structured object diffing (`diffJson`), meaning key ordering is ignored and only genuine value or structural differences trigger failures.

> [!TIP]
> **Dynamic Fields & Volatile Data:** Have fields that naturally change on every request (like `updated_at` timestamps or random UUID tokens)? Vantage runs responses through a **Noise Filter** prior to diffing so volatility doesn't cause false positives. See [Noise Filtering](/docs/configuration/noise-filtering).

---

## Failure Categories

When a test fails, Vantage categorizes the root cause into one of four distinct failure types:

| Category | Description |
| :--- | :--- |
| `STATUS_CODE_CHANGED` | The actual HTTP status code differed from the expected status (e.g. expected `200`, received `500`). |
| `HEADER_CHANGED` | A recorded header is missing from the response or its value has changed. |
| `BODY_CHANGED` | The structure, keys, or values within the JSON response body do not match the baseline. |
| `CONNECTION_ERROR` | Vantage was unable to connect to the target server (e.g. server crashed, timeout, or wrong port). |

## Interactive Terminal Diff Output

When a test fails, Vantage's terminal UI displays an isolated failure card highlighting the exact discrepancy:

```text
--------------------------------------------------------------------
┌──────────────────────────────────────────────────────────────────┐
│                        POST-API-USERS-1                          │
│                                                                  │
│              EXPECT STATUS     │     ACTUAL STATUS               │
│                   200          │          200                    │
├──────────────────────────────────────────────────────────────────┤
│                          BODY DIFFS                              │
│                                                                  │
│     {                                                            │
│       "id": "usr_123",                                           │
│       "name": "Alice",                                           │
│  -    "role": "admin",                                           │
│  +    "role": "member"                                           │
│     }                                                            │
└──────────────────────────────────────────────────────────────────┘
```

- **Red (`-`)**: Present in recorded baseline, missing from current response.
- **Green (`+`)**: Newly introduced in current response, missing from baseline.
