Vantage is built for automated Continuous Integration (CI) environments. It manages application lifecycle, boots isolated ephemeral databases, and outputs industry-standard test reports.

## The `--ci` Flag

When executing in a headless CI pipeline, always pass the `--ci` flag:

```bash
vantage test --ci -c "npm start" --delay 5
```

### What `--ci` Does:
- **Headless Mode**: Replaces the interactive terminal UI with clean, streamable stdout text.
- **Exit Codes**: Exits with status code `0` when all tests pass, and code `1` if any regression or assertion fails.
- **JUnit XML Generation**: Automatically generates a standardized JUnit XML test report under `.vantage/reports/`.

## GitHub Actions

Here is an enterprise-grade GitHub Actions workflow that runs Vantage tests and publishes the resulting test summary directly to your Pull Requests:

```yaml
name: Vantage API Tests

on:
  push:
    branches: [ "main" ]
  pull_request:
    branches: [ "main" ]

jobs:
  test:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout Repository
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: 'npm'

      - name: Install Application Dependencies
        run: npm ci

      - name: Install Vantage CLI
        run: npm install -g vantage-cli

      # If your vantage.config.yaml uses containers, Docker is already 
      # running and ready on GitHub's ubuntu-latest runners.
      - name: Execute Vantage Tests
        run: vantage test --ci -c "npm start" --delay 5

      - name: Publish Test Report
        uses: mikepenz/action-junit-report@v4
        if: always() # Always publish reports even if tests fail
        with:
          report_paths: '.vantage/reports/**/*.xml'
```

## GitLab CI

Here is an equivalent pipeline configuration for GitLab CI taking advantage of GitLab's native JUnit report ingestion:

```yaml
vantage_tests:
  image: node:20
  stage: test
  services:
    - docker:dind # Required if using Testcontainers in vantage.config.yaml
  variables:
    DOCKER_HOST: tcp://docker:2375
  before_script:
    - npm ci
    - npm install -g vantage-cli
  script:
    - vantage test --ci -c "npm start" --delay 5
  artifacts:
    when: always
    reports:
      junit: .vantage/reports/**/test-set-*-junit.xml
```

## Testing Against Deployed Staging Environments

You can also use Vantage inside CD deployment pipelines (e.g. post-deploy smoke testing) by using the `--target` flag:

```bash
vantage test --ci --target https://staging-api.mycompany.com
```
