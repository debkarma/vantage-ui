title: Running Tests
description: Learn how to replay your recorded traffic against your backend.

Once you have recorded traffic into your `.vantage` directory, you can replay it against your backend to detect regressions, schema changes, and unintended side effects.

## Basic Replay

If your application is already running locally, replay your latest recorded test suite with:

```bash
vantage test
```

By default, Vantage will:
1. Target `http://localhost:3000` (or the port defined in `vantage.config.yaml`).
2. Load the **most recent** test set from `.vantage/`.
3. Replay each request chronologically, assert responses against the recorded baseline, and display interactive visual diffs.

---

## Auto-Starting Your Server (`-c`)

Instead of manually starting and stopping your server in a separate terminal, Vantage can manage your application's full lifecycle using the `-c` (command) flag:

```bash
vantage test -c "npm run dev"
```

When `-c` is provided:
- Vantage automatically boots your server.
- Waits a 3-second grace period for the server to bind its port (customize with `--delay`).
- Executes the tests.
- Gracefully kills the child process upon completion.

### Customizing Startup Delay (`--delay`)
If your backend takes longer to compile or initialize (e.g., heavy Spring Boot or large TypeScript apps), use `--delay` to specify wait time in seconds:

```bash
vantage test -c "npm run build && npm start" --delay 5
```

---

## Targeting a Specific Test Set

By default, Vantage replays the latest test set. To replay a historical test set:

```bash
vantage test --test-set test-set-0 -c "npm run dev"
```

---

## Testing Remote Environments (`--target`)

To verify staging, preview, or production deployments, override the target base URL:

```bash
vantage test --target https://staging-api.myapp.com
```

---

## Continuous Integration (`--ci`)

For automated test runs inside CI/CD pipelines (GitHub Actions, GitLab CI, CircleCI), pass the `--ci` flag:

```bash
vantage test -c "npm start" --ci
```

In CI mode:
- The interactive Ink terminal UI is replaced with clean, pipeable stdout text logs.
- Automatically generates a JUnit XML report (`.vantage/reports/test-run-X/test-set-Y-junit.xml`).
- Exits with status code `0` if all tests pass, and status code `1` if any assertions fail.

---

## Chronological Execution & Statefulness

Vantage guarantees **chronological execution**. When replaying, it sorts test cases based on their high-precision `metadata.created_at` timestamp:

1. `post-api-users-1.yaml` (Creates the resource)
2. `get-api-users-1.yaml` (Reads the newly created resource)
3. `delete-api-users-1.yaml` (Cleans up the resource)

This ensures stateful flows execute reliably in the exact same sequence as real user traffic.
