---
title: JUnit XML Reports
description: Generate standard JUnit XML reports for CI dashboards.
---

While the terminal output is great for local development, CI/CD platforms usually require test results in a structured format to generate visual test reports and identify flaky tests.

Vantage natively supports exporting test results to the industry-standard **JUnit XML format**.

## Generating the Report

To generate an XML report, append the `--reporter=junit` flag to your test command:

```bash
vantage test --ci -c "npm start" --reporter=junit
```

By default, this will create a `vantage-report.xml` file in the root of your project directory.

## Changing the Output Path

If you need the report saved in a specific directory (for example, an artifacts directory your CI provider expects), use the `--output` flag:

```bash
vantage test --ci --reporter=junit --output=./test-results/vantage.xml
```

## Consuming Reports in CI

### GitHub Actions

You can use third-party actions to read the JUnit XML and create inline annotations on your Pull Requests:

```yaml
- name: Run Vantage Tests
  run: vantage test --ci -c "npm start" --reporter=junit

- name: Publish Test Report
  uses: mikepenz/action-junit-report@v4
  if: success() || failure() # always run even if tests fail
  with:
    report_paths: 'vantage-report.xml'
```

### GitLab CI

GitLab natively understands JUnit XML files and will display them in the MR widget. You simply need to expose the file as a report artifact:

```yaml
vantage_tests:
  script:
    - vantage test --ci -c "npm start" --reporter=junit
  artifacts:
    when: always
    reports:
      junit: vantage-report.xml
```
